# ADR-0006: Frontend stack and component library

- Status: Accepted · Date: 2026-11-14

## Context
The spec requires Next.js, React, TypeScript, Tailwind and "a maintainable component library", with a responsive UI and multilingual support later.

## Decision
- **Next.js 16.4** (App Router) with Cache Components and Partial Prefetching as generated by `create-next-app`, and `output: "standalone"` for a small non-root runtime image.
- **Tailwind CSS 4** with all colours, fonts and radii defined as theme tokens in `globals.css`.
- **Component library: local, shadcn-style components** (`src/components/ui`) built on `class-variance-authority` and `tailwind-merge`, with `lucide-react` icons. Components are owned in-repo (no opaque runtime dependency) and are easy to restyle. Radix primitives will be added per component when interactive widgets (dialogs, sliders, menus) are needed.
- **Visual identity: "night arcade"**: deep ink surfaces, a violet brand colour and a teal "match" signal. Space Grotesk for display text, Inter for body. Dark-only in Stage 1.
- **Testing**: Vitest with Testing Library on `happy-dom`. jsdom's current release needs Node ≥ 20.19, and the dev machine has 20.18.
- **i18n**: user-facing strings are in components for now. A library (e.g. next-intl) will be chosen when the second language is scheduled, and all strings extracted then.
- TypeScript 5.9 (TypeScript 7 is not yet confirmed compatible with Next.js tooling).

## Consequences
- A light theme needs only a second token set.
- Extracting strings for i18n is deferred work and becomes larger with every page added.
